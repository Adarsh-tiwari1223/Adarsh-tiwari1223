What Goes Wrong 02 / 05

Why standard POM gets messy in real projects

Most tutorials teach you to put everything in a single Page class. Here is what happens when the app gets bigger:

1. High Coupling Between UI and Business Logic

When a button selector changes, you edit the page class. When product changes the business flow, you edit the exact same file. It quickly becomes a fragile codebase where changes create unexpected breakages.

2. The Assertion Trap

If you put assertions inside page methods (like checking if a dashboard appeared), you cannot reuse that same method for testing invalid credentials without writing duplicate helpers.

3. Multi-Page Journeys Have No Clear Home

Real enterprise flows (like onboarding an employee, generating payroll, and verifying an email) cross 3 or 4 pages. Forcing all of that into one page class breaks modularity.

Takeaway: Pages interact. Workflows orchestrate. Tests validate.

The 3 Layers 03 / 05

Separating UI, Workflows & Tests

Giving each layer one clear responsibility keeps changes isolated and clean:

LAYER 1 Pages Layer (UI & Locators)

Job: Holds selectors and raw actions (click, fill, select_option).

If a frontend ID or CSS class changes, you update only this file. Tests and workflows don't change.

LAYER 2 Workflows Layer (Business Logic)

Job: Chains page actions into reusable user journeys (login_as_admin(), create_employee()).

If a business step changes, update the workflow. Your page locators stay untouched.

LAYER 3 Tests Layer (Validation)

Job: Test scenarios, test data fixtures, and assertions (assert ...is_visible()).

Tests stay short, readable, and focused purely on whether the outcome was correct.

Flow: Tests call Workflows → Workflows use Pages → Pages drive Browser

Code Example 04 / 05

How the code looks in Python

Notice how simple each class remains:

1. Page Class (pages/login_page.py)
class LoginPage: def __init__(self, page): self.page = page self.username = page.locator("input[name='username']") self.password = page.locator("input[name='password']") self.submit_btn = page.locator("button[type='submit']") def enter_credentials(self, user, pwd): self.username.fill(user) self.password.fill(pwd) self.submit_btn.click()
2. Workflow Class (workflows/auth_workflow.py)
class AuthWorkflow: def __init__(self, page): self.login_page = LoginPage(page) def login_as_user(self, user): self.login_page.page.goto("/auth/login") self.login_page.enter_credentials(user.name, user.pwd)
3. Test Function (tests/test_auth.py)
def test_valid_admin_login(page, admin_user): AuthWorkflow(page).login_as_user(admin_user) assert page.locator("[data-testid='dashboard-welcome']").is_visible()
Result: Zero assertions in pages. Zero selectors in tests.
